
# AI ファイルマネージャー

## 概要

AI ファイルマネージャーは、Gemini API を活用したスマートなファイル管理アプリケーションです。ファイルのテキスト要約、AIチャットアシスタント、インテリジェントな検索、ファイル操作（アップロード、ダウンロード、フォルダ作成、削除）、多言語対応（英語/日本語）などの機能を提供し、ユーザーがファイルをより効率的に整理、検索、理解できるように支援します。

**重要: このアプリケーションをクラウド上で完全に機能させるには、別途AWS上にバックエンドAPIを構築・設定する必要があります。これには、Amazon API Gateway、AWS Lambda、Amazon S3、Amazon DynamoDB、そして適切なIAMロールとポリシーの設定が含まれます。フロントエンドの `apiService.ts` 内の `API_BASE_URL` や認証方法も、構築したバックエンドに合わせて適切に設定する必要があります。**

## 前提条件

*   Node.js (推奨バージョン: 18.x 以上)
*   npm または yarn
*   AWS アカウントおよびAWSサービス（API Gateway, Lambda, S3, DynamoDB, IAM）に関する基本的な知識
*   Google Gemini API キー

## APIキーおよび設定

### Google Gemini API キー (バックエンドでの利用推奨)
このアプリケーションはバックエンドで Google Gemini API を使用します（ファイルの要約、AIチャット機能など）。
**本番環境およびクラウド化された環境では、Gemini APIキーはAWS Lambda関数の環境変数として安全に設定し、バックエンドAPI経由で呼び出すことを強く推奨します。** フロントエンドにAPIキーを直接埋め込むことは避けてください。

開発初期段階でフロントエンドから直接Gemini APIをテストする場合（`apiService.ts` の `USE_LOCAL_FALLBACK = true` の時など）は、プロジェクトのルートディレクトリに `.env` ファイルを作成して以下のように設定できます。
```env
API_KEY=YOUR_GEMINI_API_KEY_FOR_FRONTEND_TESTING_ONLY
```
**注意:** `YOUR_GEMINI_API_KEY_FOR_FRONTEND_TESTING_ONLY` は実際のAPIキーに置き換えてください。この `.env` ファイルはGitの追跡対象から除外することを推奨します。Viteは `vite.config.ts` の設定を通じて、このキーを `process.env.API_KEY` としてフロントエンドコードから利用可能にします。**繰り返しますが、これは開発・テスト用であり、本番のクラウド環境ではバックエンドでAPIキーを管理してください。**

### AWS バックエンド API 設定
フロントエンドの `apiService.ts` ファイル内で、`API_BASE_URL` 定数を、Amazon API Gatewayでデプロイしたご自身のAPIエンドポイントURLに置き換える必要があります。
例: `const API_BASE_URL = 'https://xxxxxxxxxx.execute-api.your-region.amazonaws.com/prod';`

また、APIの認証方法（例: Amazon Cognitoを用いたトークンベース認証、IAM認証など）をバックエンドで実装し、フロントエンドの `apiService.ts` 内の `getAuthToken` 関数や `apiRequest` 関数内の認証ヘッダー設定を適宜修正する必要があります。

## 開発環境

このプロジェクトは `Vite` を使用して開発環境を構築・実行します。

*   **`package.json`**: プロジェクトの依存関係とスクリプトを定義。
*   **`vite.config.ts`**: Vite の設定ファイル。Reactプラグインの有効化や、開発時の環境変数読み込み設定が含まれています。
*   **`index.html`**: アプリケーションのエントリーポイント。
*   **`index.tsx`**: ReactアプリケーションをマウントするメインのTypeScriptファイル。
*   **`apiService.ts`**: バックエンドAPIとの通信ロジックを記述します。このファイルがクラウドバックエンドと連携する主要なポイントです。

## インストール

1.  プロジェクトのルートディレクトリに移動します。
2.  依存関係をインストールします。

    ```bash
    npm install
    # または
    yarn install
    ```

## 開発サーバーの起動 (フロントエンドのみ)

フロントエンドアプリケーションをローカルで起動するには、以下のコマンドを実行します。

```bash
npm run dev
# または
yarn dev
```
これにより、Vite開発サーバーが起動します。
**この状態では、`apiService.ts` の `USE_LOCAL_FALLBACK` が `true` に設定されていればローカルのダミーデータで動作しますが、`false` に設定されている場合は、AWS上にバックエンドAPIが構築・設定され、`API_BASE_URL` が正しく設定されていない限り、ファイル操作などの主要機能は動作しません。**

## 主な機能 (AWSバックエンドAPI実装後)

*   **ファイルとフォルダの管理**:
    *   表示・ナビゲーション (DynamoDBからメタデータを取得)
    *   ファイルアップロード (S3へPresigned URL経由でアップロード、DynamoDBにメタデータ保存、ドラッグ＆ドロップ対応、フォルダアップロード対応)
    *   フォルダ作成 (DynamoDBにメタデータ保存)
    *   ファイル/フォルダ削除 (S3から実ファイル削除、DynamoDBからメタデータ削除。フォルダの場合は再帰的に処理)
    *   ファイルダウンロード (S3からPresigned URL経由でダウンロード)
*   **AI機能 (バックエンドLambda経由でGemini API利用)**:
    *   テキストファイル（.txt, .md, .pdf, .docxなど）の要約
    *   ファイルコンテキストに基づいたAIチャットアシスタント
*   **検索とフィルタリング**:
    *   ファイル名によるフィルタリング (バックエンドAPIが対応)
    *   (将来的には) AIによるコンテンツベースの検索
*   **その他**:
    *   音声入力による検索およびAIチャット (ブラウザが対応している場合)
    *   多言語対応（英語、日本語）

## AWSバックエンド構築の概要

フロントエンドと連携するバックエンドAPIをAWS上に構築するための主要なコンポーネントは以下の通りです。

1.  **Amazon API Gateway**:
    *   フロントエンドからのHTTPリクエストを受け付けるAPIエンドポイントを作成・管理します。
    *   各エンドポイント（例: `/files`, `/folders`, `/files/{id}/summarize`）を対応するAWS Lambda関数にルーティングします。
    *   認証（Cognitoオーソライザー、IAM認証など）を設定します。
2.  **AWS Lambda**:
    *   各APIエンドポイントに対応するビジネスロジックを実行するサーバーレス関数群を作成します。
        *   Node.js, Pythonなどの言語で開発。
        *   AWS SDKを使用してS3やDynamoDBを操作。
        *   ファイルアップロード処理（署名付きURL生成、完了通知処理）。
        *   ファイル/フォルダのCRUD操作ロジック。
        *   Gemini APIを呼び出す要約処理やAIチャット応答処理。
        *   **Gemini APIキーはLambda関数の環境変数として安全に設定します。**
        *   Lambda関数で外部ライブラリ（例: 以前の `uuid` のようなもの）を使用する場合、ライブラリをLambdaレイヤーとしてデプロイするのが推奨される方法です。これにより、デプロイパッケージのサイズを小さく保ち、ライブラリのバージョン管理を一元化できます。`uuid`のような特定のID生成ライブラリが不要な場合でも、他の外部ライブラリを使用する可能性は常にあります。
            *   **Lambdaレイヤーの作成 (推奨):**
                1.  ローカルマシンに `my-layer/nodejs` というディレクトリ構造を作成します。
                2.  ターミナルで `my-layer/nodejs` ディレクトリに移動し、`npm init -y` を実行後、`npm install <library-name>` で必要なライブラリをインストールします。これにより、`my-layer/nodejs/node_modules` と `my-layer/nodejs/package.json` などが作成されます。
                3.  `my-layer` ディレクトリ直下にある `nodejs` フォルダをZIPファイルに圧縮します（ZIPファイルのルートには `nodejs` フォルダが入るようにします）。
                4.  AWS Lambdaコンソールの「レイヤー」セクションで新しいレイヤーを作成し、このZIPファイルをアップロードします。互換性のあるランタイムを選択します。
                5.  作成したレイヤーをLambda関数に追加します。これで、Lambda関数のコードから `import ... from '<library-name>';` のように直接ライブラリをインポートできるようになります。Lambda関数のデプロイパッケージには、ライブラリを含める必要がなくなります。
            *   **デプロイパッケージにライブラリを含める場合 (代替手段):**
                1.  Lambda関数用のローカルディレクトリを作成します (例: `my-lambda-function`)。
                2.  そのディレクトリに `index.mjs` (または `index.js`) を配置します。
                3.  そのディレクトリ内で `npm init -y` を実行し、必要なライブラリを `npm install <library-name>` でインストールします。
                4.  `index.mjs` と生成された `node_modules` フォルダを含む、ディレクトリの内容全体をZIPファイルに圧縮します。
                5.  AWS Lambdaコンソールの「コードソース」から、このZIPファイルをアップロードします。
3.  **Amazon S3**:
    *   アップロードされたファイルの実データを保存するバケットを作成します。
    *   ライフサイクルポリシー、バージョニング、暗号化などを設定。
    *   **CORS設定**: フロントエンドからの署名付きURL (Presigned URL) による直接アップロード（特に `PUT` リクエスト）を許可するために、S3バケットに適切なCORS設定が必要です。これには、`AllowedMethods` に `PUT` を含め、`AllowedOrigins` にフロントエンドのドメイン（開発中は `*` も可）を指定することが含まれます。
4.  **Amazon DynamoDB**:
    *   ファイルやフォルダのメタデータ（ID, 名前, 種類, 親ID, S3キー, MIMEタイプ, 更新日時, 所有者IDなど）を格納するテーブルを作成します。
    *   適切なプライマリキーとグローバルセカンダリインデックス（GSI）を設計し、効率的なクエリを実現します（例: `parentId` と `name` によるフォルダ内一覧取得）。
5.  **AWS IAM**:
    *   API Gateway、Lambda関数、S3バケット、DynamoDBテーブル間のアクセス権限を管理するためのIAMポリシーとIAMロールを適切に設定します。
    *   最小権限の原則に従い、各コンポーネントが必要な権限のみを持つようにします。
    *   **特に、Lambda関数にアタッチするIAMロールのS3アクセスポリシーでは、`Resource` に指定するS3バケット名が、実際に使用するバケット名（例: `arn:aws:s3:::your-actual-bucket-name/*`）と完全に一致していることを確認してください。**

## 注意事項
* このREADMEで説明されているクラウド化は、フロントエンド側の準備と、バックエンド構築の概要を示すものです。AWS上での具体的なリソース構築、Lambda関数のコード開発、セキュリティ設定（認証・認可、ネットワーク設定など）、テスト、デプロイは別途行う必要があります。
* Gemini APIの利用には、利用規約の遵守と、適切なAPIキー管理が不可欠です。
* `index.html`には`importmap`の記述がありますが、Viteによる開発では主に`package.json`の依存関係が利用されます。
